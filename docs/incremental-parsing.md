# 实时预览与增量解析

`MarkdownParseSession` 是解析层能力，不依赖 HuxerUI。demo 的实时预览负责输入、
输入合并和发布快照，两者可以独立使用。`ParseMarkdown` 仍是无状态的全量解析函数。

## 会话契约

```cpp
MarkdownParseSession parser({.soft_break_mode = SoftBreakMode::LineBreak});
auto first = parser.Update("# Article\n\nFirst paragraph.\n\nSecond paragraph.\n");
auto next = parser.ApplyEdit({.start_byte = parser.Source().size(),
                              .inserted_text = "\nAppended paragraph.\n"});
auto stats = parser.LastParseStats();
```

- `Update` 接受完整 UTF-8 源码；`ApplyEdit` 在当前源码上替换一个范围。
- `start_byte` 和 `removed_bytes` 均为 UTF-8 字节，边界必须落在 Unicode 标量边界。
  HuxerUI 的文本选区使用 UTF-16 坐标，应用必须转换，不能直接代入。
- 初始源码为空，初始快照有效。相同输入不调用 MD4C，返回同一身份的快照。
- 返回值是不可变文档，旧快照在会话更新或销毁后仍有效，只要调用方保留它。
- 构造时固定 `ParseOptions`，修改配置请新建会话。会话不可复制或移动。
- 同步执行；会话需限制在单线程或通过外部串行化访问。快照可交给 UI 线程。
- `Source()` 借用会话源码，成功替换后失效；`Document()` 借用当前快照句柄，
  要跨更新保存旧快照必须复制返回值。
- 越界抛 `out_of_range`，拆分标量或无效 UTF-8 抛 `invalid_argument`，超过大小/深度限制
  抛 `length_error`。任何更新失败均保留上次成功的源码、快照与统计。

## 复用规则与回退

解析时由 MD4C 的真实顶层节点回调记录重启点，不通过搜索 `#` 猜测节点。
当前支持已换行结束的顶层 ATX 标题首行，以及空行之后、以直接普通文本开始的顶层段落首行。
不使用代码块内部、嵌套容器内部、跨行 span 开头或末尾未换行的行作为重启点。
段落首行的字面 BOM 也被排除，避免片段起点改变 BOM 的解析语义。

更新先计算两份源码的相同前缀，选择首行完全未变的最后一个有效重启点；复制之前的
顶层 AST 块，仅将该点至新源码末尾交给 MD4C。不会复用变化位置之后的后缀，避免容器、
围栏代码、列表松紧等向后影响。结果应与相同选项下的 `ParseMarkdown` 完全一致。

[CommonMark 引用定义](https://spec.commonmark.org/0.31.2/#link-reference-definitions)
可以影响前文的引用链接。任一旧/新源码含字面 `]:` 时保守地全量解析，包括代码或转义中的
误命中。这覆盖当前启用语法的定义形式；没有可证明安全的重启点也全量解析。
脚注扩展的定义同样包含字面 `]:`，因此定义新增、删除、编号或引用关系变化均在这条全量回退
路径内，不会复用过期编号或重复拼接文末定义区。新增扩展仍须重新审查复用条件。

## 统计与开销

| 字段 | 含义 |
| --- | --- |
| `mode` | `Unchanged`、`Incremental` 或 `Full` |
| `parsed_bytes` | 本次文档主解析交给 MD4C 的 UTF-8 字节数，不含可选源码区间的片段验证解析 |
| `reused_blocks` | 免于重新解析的顶层块数；不变输入时为全部块 |
| `total_blocks` | 新快照的顶层块数 |

这是解析工作复用，不是每次更新整体 O(改动大小)。UTF-8 验证、源码比较/复制、引用标记扫描
和保留 AST 的复制仍有线性开销。新快照没有持久化共享子树；普通 `Markdown` 仍组合全文。
可见区按需挂载由独立的 `VirtualizedMarkdown` 提供。越靠近文首的编辑，通常需要解析越多内容。
任意字节流输入使用 `MarkdownStream`，完整文本追加可以用会话的 `Append()`；详见
[流式与虚拟化契约](streaming-and-virtualization.md)。

## Demo 更新策略

默认开启「实时预览」。`TextField.OnChanged` 回调收到文本改变后启动一个 120 ms 窗口；
期间继续输入只替换待渲染源码，不延后截止时间。到期同步解析最新源码并发布快照；
后续输入启动下一窗口，因此长按按键也会持续更新，无输入时不循环启动任务。
这属于尾沿节流与输入合并，不再使用等待停止输入的防抖。光标/选区变化不发起解析。
任务还校验请求序号，避免已取消的任务发布结果。
「渲染」立即发布当前源码，关闭实时预览后仍可手动操作；重新开启会预览当前草稿。
切换/重置样例取消待处理任务并立即解析，卸载时取消任务。
解析失败显示错误并保留上次成功预览。主题变化继续使用快照，编辑保留滚动，样例切换/重置滚动。

节流并不把解析转移到后台。demo 在 UI 线程执行解析，大文档仍可能阻塞；生产应用可以将会话
交给串行 worker，并在 UI 发布前检查请求版本，不应在多个 worker 上同时访问一个会话。

## 验证

`markdown.incremental` 将快照 AST 与全量解析逐项对照，包括 4,200 次确定种子的随机编辑、
连续追加、Unicode、CRLF/CR、BOM、NUL、引用定义、列表/引用/代码/表格及配置组合。
长文档尾部编辑验证复用超过 200 个顶层块、MD4C 解析字节少于原文十分之一。
另有失败状态保持、字节边界、大小/深度限制、快照生命周期与不变输入检查。

`markdown.preview` 使用真实应用与虚拟时间验证 120 ms 输入合并、持续按键重复期间多次刷新、
停止输入后最后一次更新、实时开关取消任务、
手动渲染、样例切换/重置、尾部编辑增量统计和滚动保留，并保留链接、主题、布局与自定义渲染回归。
